# Weekly Review

直近7日間の記憶を対象に、本人へ提出する週次レビューを作る。cron から
`--deliver discord` で実行され、結果は Discord のホームチャンネルへ届く。

## 手順

1. 実行日時を Asia/Tokyo で確認し、前日までの7日間を対象期間とする。
   開始日・終了日を具体的な `YYYY-MM-DD` に確定する。例えば月曜
   2026-11-09 の実行なら 2026-11-02 〜 2026-11-08 とする。
2. `hindsight_recall` を以下の4観点で各1回呼ぶ。引数は `query` だけとし、
   毎回「対象期間: <開始日> 〜 <終了日>（Asia/Tokyo、両端を含む）」と
   その観点の検索文を書く。日付は1で確定した値に置き換える。
   - 期間内に起きた出来事、新しく始めたこと、完了・解決したこと。
   - 期間内に話した未完了・継続中のこと、約束や今後の予定、期限と現状。
   - 期間内に本人が明示した考え・好み・方針の変化と、その前後の発言。
   - 期間内の発言と以前の記憶の食い違い、撤回・訂正、確認が必要なこと。
   1回の結果は設定上4096 tokens程度で、全記憶を網羅しない。同じ広い検索を
   繰り返さず、各結果の根拠と重複を整理してから次の観点へ進む。
   このレビューでは `hindsight_reflect` は呼ばない。
3. 取得した記憶を自分で照合・統合する。queryの日付は厳密な期間フィルタでは
   なく、範囲の片方の日付だけが検索に使われたり、期間外の記憶も返る。
   記憶本文の日付と出来事・発言の対応を確認し、期間内の動きが確認できる項目
   だけを載せる。過去の記憶は比較の背景に使い、今週の出来事と混同しない。
   日付や根拠が曖昧な重要項目があれば、同じ対象期間とその項目を指定した
   `hindsight_recall` を追加で1回だけ呼び、裏を取る（合計4〜5回）。
   根拠が取れない項目は出さない。記憶に無いことを推測で補わない。
4. 下のテンプレートで報告する。

## 報告テンプレート

```
## 週次レビュー (YYYY-MM-DD 〜 YYYY-MM-DD)

### 未完了・継続中
- <項目>: <現状> — 根拠: <記憶の要点 / 日付>

### 変更
- <項目>: <前 → 後> — 根拠: <記憶の要点 / 日付>

### 矛盾・要確認
- <項目>: <記憶A> と <記憶B> が食い違う — どちらが正しいか確認したい

### 今週の新規
- <項目> — 根拠: <記憶の要点 / 日付>
```

## ルール

- 本人が明示した事実と、文脈から推測しただけの内容を必ず区別して書く。
  推測は推測だと明記する。推測を事実として書かない。
- 根拠のない項目、挨拶や雑談、一時的な連絡事項は載せない。
- 変化が何も無い週は、本文に `[SILENT]` とだけ書いて終了する。他の文字列を
  出力しない。
- 個人情報や秘匿値（トークン、パスワード等）は本文に転記しない。
